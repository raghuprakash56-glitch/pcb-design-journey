# Contributing to PCB Design Journey

Thank you for your interest in contributing to the PCB Design Journey project! This document provides guidelines for contributing.

## Code of Conduct

- Be respectful and inclusive
- Provide constructive feedback
- Focus on the work, not the person
- Help others learn and grow

## How to Contribute

### 1. Reporting Issues
If you find a problem or have a suggestion:
- Check existing issues to avoid duplicates
- Provide clear, descriptive titles
- Include relevant details and context
- Add screenshots or examples if applicable

### 2. Submitting Documentation
- Ensure clarity and accuracy
- Follow the existing format and structure
- Include examples and references
- Proofread for grammar and spelling

### 3. Adding Projects or Examples
- Include complete schematic files
- Provide detailed documentation
- Explain the project's purpose and learning outcomes
- Include bill of materials (BOM) when applicable

### 4. Code Contributions
- Follow PEP 8 for Python code
- Add comments explaining complex logic
- Include unit tests where applicable
- Update documentation accordingly

## Pull Request Process

1. **Fork the repository** and create a feature branch
   ```bash
   git checkout -b feature/your-feature-name
   ```

2. **Make your changes**
   - Keep commits atomic and well-described
   - Follow the project's style and structure

3. **Update documentation**
   - Update README.md if needed
   - Add comments to code
   - Update relevant guides or tutorials

4. **Test your changes**
   - Verify all links work
   - Check formatting and readability
   - Ensure files open correctly

5. **Commit and push**
   ```bash
   git add .
   git commit -m "Clear description of changes"
   git push origin feature/your-feature-name
   ```

6. **Create a Pull Request**
   - Use a clear title
   - Describe the changes in detail
   - Reference any related issues
   - Wait for review and feedback

## Commit Message Guidelines

Use clear, descriptive commit messages:
- **Good:** `Add schematic design guide for basic circuits`
- **Avoid:** `Fixed stuff` or `Update docs`

Format:
```
[Type] Brief description

Detailed explanation if needed.
- Bullet point for specific changes
- Another important detail
```

Types: `Add`, `Update`, `Fix`, `Docs`, `Refactor`, `Remove`

## File Naming Conventions

- Use lowercase with hyphens: `my-project-name`
- Be descriptive: `beginner-led-circuit` not `project1`
- For documents: `topic-subtopic.md`

## Documentation Standards

- Use Markdown for all documentation
- Include table of contents for longer documents
- Add code blocks with syntax highlighting
- Include diagrams and images where helpful
- Cite sources and references

## Questions or Need Help?

- Open an issue with the `question` label
- Check existing discussions
- Ask in project discussions if available

## Recognition

Contributors will be recognized in:
- The project's CONTRIBUTORS.md file (when created)
- Relevant pull request comments
- Project statistics and history

Thank you for making this project better! 🙌
